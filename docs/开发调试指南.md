# 开发调试指南

> 面向本仓库（Go 后端 + Vue3 前端）的本地开发、联调与 VSCode 调试。
> 前置工具：Go 1.26+、Node 18+（推荐 22）、MySQL 8.4、Redis 7（经 SSH 隧道映射到本机）。

---

## 1. 环境准备（一次性）

### 1.1 数据库（SSH 隧道）

MySQL 与 Redis 跑在服务器上，通过 SSH 本地转发映射到本机回环：

```
# ~/.ssh/config（Windows: C:\Users\<你>\.ssh\config）
Host study-db
    HostName 211.101.246.225
    User <你的SSH用户>
    ServerAliveInterval 30
    ServerAliveCountMax 3
    ExitOnForwardFailure yes
    LocalForward 3306 127.0.0.1:3306
    LocalForward 6379 127.0.0.1:6379
```

```powershell
ssh -N study-db        # 建立隧道后保持挂着；-N 表示不执行远程命令
```

验证：

```powershell
# 3306 通：返回 MySQL 版本字符串（如 8.4.11）
Test-NetConnection 127.0.0.1 -Port 3306
# 6379 通：需要密码（服务器 Redis 设了 requirepass）
```

> 端口被本机服务占用时换本地端口（如 13306），并在 .env 里同步改 DSN——
> 本地端口与远端端口不需要一致。

### 1.2 初始化数据库

```powershell
cd D:\personal\test-db
# 用你惯用的客户端连 127.0.0.1:3306 执行 sql/init.sql；或命令行：
mysql -h 127.0.0.1 -P 3306 -u root -p < sql\init.sql
```

种子账号密码见 `docs/项目系统文档.md` §9。

### 1.3 后端配置

```powershell
cd D:\personal\test-db\server
Copy-Item .env.example .env
# 编辑 .env：填 MYSQL_DSN 密码、REDIS_PASSWORD、JWT_SECRET（>=32 字节随机串）
# JWT_SECRET 可用 PowerShell 生成：
# -join ((1..48) | ForEach-Object { [char]((97..122) + (48..57) | Get-Random) })
```

## 2. 日常启动

### 2.1 后端（Go）

```powershell
cd D:\personal\test-db\server
go run ./cmd/api        # 监听 :8080
```

### 2.2 前端（Vite）

```powershell
cd D:\personal\test-db\web
npm install             # 首次
npm run dev             # http://localhost:5173，/api 与 /uploads 已代理到 8080
```

手机真机调试：Vite 默认只监听 localhost，让手机访问同一局域网：

```powershell
npm run dev -- --host   # 终端会打印 http://<局域网IP>:5173，手机浏览器打开
```

注意：手机访问走 IP 而非 localhost，Cookie 的 SameSite=Lax 在跨 host 时仍可携带
（同 site 不同 port 不算跨站）；若遇到 Cookie 不带回，检查后端 CORS 白名单是否
包含 `http://<局域网IP>:5173`（`server/cmd/api/main.go` 里加一条即可）。

## 3. VSCode 调试配置

仓库根 `.vscode/` 已带三样：`launch.json`（调试）、`tasks.json`（构建任务）、
`settings.json`（Go 与 Vue 推荐）。推荐扩展（`extensions.json` 一键安装）：

- **Go**（golang.go，内置 delve 调试器）
- **Vue - Official**（vue.volar，TS + .vue 支持）

### 3.1 调试后端（断点直接命中）

1. 打开 `server/cmd/api/main.go` 或任意 handler，在行号左侧点一下加断点
   （推荐试试点：`internal/auth/service.go` 的 `Login()` —— 走一遍登录全流程；
   `internal/biz/handler.go` 的 `UpdateItem()` —— 看 owner 权限判定）
2. F5 或运行面板选 **"调试后端 api (Go)"** —— delve 编译并启动，断点即停
3. 常用面板：VARIABLES 看变量、WATCH 加表达式、CALL STACK 看中间件调用链
   （能直观看到 `JwtAuth → RequirePermission → handler` 的顺序）

> delve 首次调试会自动 `go install`（GOPATH/bin 下），无需手动装。
> 断点没命中？确认 launch.json 的 `cwd` 是 `${workspaceFolder}/server`
> —— .env 要从 server/ 目录加载。

### 3.2 调试前端（Chrome DevTools in VSCode）

1. 先启动 Vite：运行任务 **"web: dev server"**（Terminal → Run Task），或手动 `npm run dev`
2. F5 选 **"调试前端 web (Chrome)"** —— 会拉起一个独立 Chrome 窗口指向 5173
3. .vue/.ts 文件里直接打断点（如 `src/utils/request.ts` 的 401 刷新逻辑，
   观察"并发只刷一次"的单飞行为）

> 需要装 **JavaScript Debugger**（VSCode 内置，无需额外扩展）。
> 手机端调试用 Chrome `chrome://inspect` 远程调试，VSCode 这套用于桌面 Chrome。

### 3.3 一键任务（Terminal → Run Task）

| 任务 | 作用 |
|------|------|
| `server: build` | `go build ./...` 编译检查 |
| `server: vet` | `go vet` 静态检查 |
| `server: run` | 直接跑后端（不带调试器） |
| `web: dev server` | 启动 Vite |
| `web: build` | 生产构建（TS 类型检查 + 打包） |

## 4. 联调调试技巧

### 4.1 看清楚双 Token 的流动（本系统最值得盯的机制）

Chrome DevTools → Network：

1. `POST /api/v1/auth/login`：Response Headers 里有
   `Set-Cookie: refresh_token=...; HttpOnly; Path=/api/v1/auth; SameSite=Lax`
   —— JS 读不到它，Application → Cookies 面板能看到。
2. 任意业务请求：Request Headers `Authorization: Bearer eyJhbG...`（access 只活 15 分钟）。
3. 等 15 分钟（或把 .env 的 `ACCESS_TTL` 调成 `2m` 重启后端加速实验）：
   下一个请求 401 → 拦截器发 `POST /auth/refresh` → 拿新 access 重放原请求。
4. **复现重用检测**：DevTools 里手动再发一次 `POST /auth/refresh`（用旧 Cookie 不行——
   Cookie 已换；正确姿势是登录两次取两个 refresh，或看后端日志）。更简单的办法：
   Application 面板把 refresh_token 复制出来，用 curl 手动刷一次，再让页面也刷一次
   —— 第二次必触发 REUSE_DETECTED，返回 401 并撤销整个 family，审计日志有记录。

### 4.2 Redis 会话态观察

SSH 到服务器，`redis-cli -a <密码>`：

```
KEYS auth:*                          -- 看全部会话 key
GET  auth:refresh:<sha256>           -- 白名单记录（user_id/family_id/status）
TTL  auth:refresh:<sha256>           -- 剩余寿命（读不会重置，轮换才是新 key 新 TTL）
GET  auth:fail:zhangsan              -- 登录失败计数（连错 5 次看它涨）
SMEMBERS auth:family:<fid>           -- 一次登录签发的一串 refresh
```

### 4.3 权限变更即时生效实验

1. zhangmei（member）登录，确认看不到"成员管理"入口
2. 用 admin 在用户管理里把 zhangmei 升为 family_admin
3. zhangmei 立即被踢下线（改角色撤销全部会话）→ 重新登录 → 菜单出现管理功能

### 4.4 删除用户的责任转移实验

1. zhangsan（家庭管理员）在成员管理里删除 zhangmei，接收人选 zhangsan
2. 观察：zhangmei 名下物品 owner 变为 zhangsan，物品详情的历史时间线多出
   "责任移交"记录，creator 仍是 zhangmei（提交人历史不变）

### 4.5 常见问题

| 现象 | 排查 |
|------|------|
| 后端启动报 `连接 MySQL 失败` | 隧道是否还挂着（`ssh -N study-db`）；DSN 密码；本机 3306 是否被本机 MySQL 占用 |
| Redis 报 `NOAUTH` | .env 的 REDIS_PASSWORD 没填或填错 |
| 登录 200 但刷新页就掉线 | 前端 axios 是否 `withCredentials: true`；后端 CORS 是否精确回显了 Origin |
| 401 死循环 | 检查 JWT_SECRET 是否改过（改过则旧 access 全失效，属正常，重登即可） |
| 图片显示 404 | 图片走 `/uploads`，确认 Vite proxy 配了 `/uploads` 转发 |
| Gin 路由 panic | `go run` 报 route conflict 时把终端输出发给 Claude 定位 |

## 5. 生产部署要点（学习备忘）

- 前端 `npm run build` → `web/dist/`，由 Nginx 托管并把 `/api`、`/uploads` 反代到 Go 服务
- Nginx 上做 TLS 终止；此时 .env 的 `COOKIE_SECURE=true`
- 后端 `go build -o api.exe ./cmd/api`，单二进制 + uploads/ 目录即可部署
- 前端与 API 同域（反代）后，CORS 中间件自然不生效，无需改动
