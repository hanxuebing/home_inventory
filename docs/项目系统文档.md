# 家庭物品整理收纳系统 · 项目系统文档

> 版本 v1.0 · 2026-09 · 依据《登录鉴权系统设计稿 v1.0》（JWT 双 Token + RBAC）落地
> 技术栈：Go 1.26 / Gin · MySQL 8.4 · Redis 7 · Vue 3 / TypeScript / Element Plus（移动端优先）

---

## 1. 系统概览

家庭成员在手机上录入、搜索、管理家里的物品（名称、数量、图片、备注、分类），物品在**家庭内共享可见**；系统内置三级角色控制"谁能管什么"。

```
┌─────────────────────┐      /api/v1/*  Bearer access(15m)      ┌──────────────────────┐
│  web（移动端 SPA）    │ ─────────────────────────────────────▶ │  server（Go Gin）     │
│  Vue3 + TS + EP     │ ◀────── httpOnly Cookie(refresh 7d) ──  │  :8080 单服务         │
└─────────────────────┘                                        └─────────┬─────┬──────┘
                                                                          │     │
                                            ┌─────────────────────────────┘     └──────────────┐
                                            ▼                                                  ▼
                                    ┌──────────────┐                                  ┌──────────────┐
                                    │ MySQL 8.4    │  RBAC 五表 + 家庭 + 物品/历史      │ Redis 7      │
                                    │ home_items   │  + 审计日志                       │ 会话态全在这  │
                                    └──────────────┘                                  └──────────────┘
```

- **前端** `web/`：一个移动端 Web 应用，登录后按角色**动态出现**管理功能——不再单独开发管理后台。
- **后端** `server/`：单服务 `cmd/api`，一个进程同时挂载认证、业务、管理三组路由。

## 2. 角色模型（本系统的业务核心）

| 角色 | code | 数据范围 | 能做什么 |
|------|------|---------|---------|
| 超级管理员 | `admin` | 全部家庭 | 家庭增删改查、任意用户管理（含设置角色）、审计日志、全部物品全权 |
| 家庭管理员 | `family_admin` | 本家庭 | 本家庭成员增删改查、**移交**家庭管理员、本家庭物品全权、分类管理 |
| 普通成员 | `member` | 本家庭 | 查看本家庭全部物品、录入物品、**仅改删自己负责的**物品、分类只读 |

三条关键规则（后端 handler 层强制，前端隐藏只是体验）：

1. **物品归属家庭**：所有物品查询按 `family_id` 过滤；member 也能看到家人录入的物品。
2. **提交人 vs 责任人**：物品记录 `creator_id`（谁录入的，只作展示）与 `owner_id`（谁能改删）。
   member 只能管理 `owner_id = 自己` 的物品；family_admin 对本家庭物品全权。
3. **删除用户必须指定接收人**：被删用户名下负责（owner）的物品整体移交给同家庭接收人
   （`UPDATE biz_item SET owner_id = 接收人`），每条写 `TRANSFER` 历史；接收人此后拥有
   与原提交者相同的增删改查权，历史完整保留。

管理员移交：`POST /admin/families/:id/transfer` —— 目标成员升为 `family_admin`，
原管理员降为 `member`，双方会话被撤销（强制重新登录，旧身份立即失效）。

## 3. 认证设计（对应设计稿 §3）

JWT 双 Token，一次一换（Rotation）+ 重用检测：

- **access token**（JWT，15 分钟）：内存持有，`Authorization: Bearer` 携带；payload 只放
  `sub/jti/iat/exp/iss/aud`，**权限码不进 payload**（改权限即刻生效，最多等权限缓存 30 分钟逐出）。
- **refresh token**（256bit CSPRNG 随机串，7 天）：`httpOnly + SameSite=Lax` Cookie，
  服务端只存 SHA-256 摘要进 Redis 白名单；每次 `/auth/refresh` 用旧换新，旧 token 标记 `used`。
- **重用检测**：`used` 的 refresh 再次到达 → 判定泄露 → 撤销整个 token family → 强制重登。
- **登出/踢人**：jti 进黑名单（TTL = access 剩余寿命）+ 删 refresh 白名单；禁用用户、
  改角色、改密码都会撤销该用户全部会话。

Redis key 全景（`server/internal/auth/service.go`）：

```
auth:refresh:{sha256}   {user_id, family_id, status}   TTL 7d    # refresh 白名单
auth:deny:{jti}         1                              剩余寿命   # access 黑名单
auth:fail:{username}    失败计数                        TTL 10min # ≥5 锁定
auth:perm:{user_id}     ["sys:user:list",...]           TTL 30min # 权限码缓存（角色变更逐出）
auth:family:{fid}       SET{refresh哈希}                          # token family 登记
auth:userfam:{uid}      SET{family_id}                           # 撤销用户全部会话用
```

登录防线：账号维度失败计数（5 次/10 分钟锁）、哑哈希对齐耗时（防用户名枚举）、
Argon2id（m=19456,t=2,p=1，PHC 格式，兼容 bcrypt 存量）、审计落库。

## 4. 数据模型（`sql/init.sql`）

```
sys_family ──1:N── sys_user ──M:N── sys_role ──M:N── sys_permission
                        │
                        └── biz_item.creator_id / owner_id（提交人/责任人）
sys_family ──1:N── biz_category ──1:N── biz_item（family_id 隔离可见范围）
biz_item ──1:N── biz_item_history（CREATE/UPDATE/DELETE/TRANSFER 全程留痕）
sys_audit_log（登录/敏感操作审计：操作人·IP·UA·时间·目标）
```

- RBAC 五表（user/role/permission/user_role/role_permission）+ 权限码三类型（MENU/API/BUTTON）。
- 权限码是贯穿前后端的唯一契约字符串，如 `sys:user:delete`、`biz:item:create`。
- 行级范围（全部/本家庭/本人）**不靠权限码表达**，由 handler 按角色 + `family_id` 下沉到
  WHERE 条件——对应设计稿"data_scope 下沉到 SQL"。

## 5. 后端结构（`server/`）

```
cmd/api/main.go            # 唯一入口：装配 config → MySQL/Redis → 三组路由
cmd/hashpw/main.go         # Argon2id 哈希生成工具（换密码/补种子数据）
internal/
  config/                  # .env 加载与校验（JWT_SECRET >= 32 字节）
  store/                   # MySQL（database/sql 原生 SQL，无 ORM）+ Redis 连接
  model/                   # 结构体（与表一一对应）
  pkg/resp/                # 统一响应 {code,message,data} + A0xxx 错误码
  pkg/argon2id/            # 哈希/校验/哑哈希（PHC 前缀分派，兼容 bcrypt）
  auth/                    # 认证内核：token.go(JWT) service.go(登录/轮换/重用检测) handler.go
  middleware/              # JwtAuth（验签→黑名单→status 复查→注入 permCodes）
                           # RequirePermission(code) 权限码中间件工厂
                           # CORS（Cookie 凭据跨域：精确回显 Origin）
  biz/                     # 物品/分类/上传：家庭隔离 + owner 管理权 + 修改历史
  admin/                   # 家庭/用户/审计：角色行级范围 + 移交 + 删除用户责任转移
```

中间件链固定顺序：`JwtAuth → RequirePermission(code) → handler`；
handler 内再做行级校验（家庭归属 / owner 判定）。

## 6. API 契约摘要

统一前缀 `/api/v1`，响应 `{code, message, data}`，分页 `{list,total,page,size}`。

| 方法 | 路径 | 权限码 | 说明 |
|------|------|--------|------|
| POST | /auth/login | 公开（限流） | 返回 access + user(含 permCodes)；Set-Cookie(refresh) |
| POST | /auth/refresh | Cookie | 轮换；重用检测触发则全 family 撤销 401 |
| POST | /auth/logout | 登录 | jti 进黑名单 + 删 refresh |
| GET | /auth/me | 登录 | 用户信息 + 权限码（动态菜单数据源） |
| PUT | /auth/password | 登录 | 改密；全部会话撤销 |
| GET/POST | /items | biz:item:list/create | 模糊搜索(keyword) + 分类筛选 + 分页；家庭隔离 |
| GET | /items/:id | biz:item:list | 详情（含提交人/责任人） |
| GET | /items/:id/history | biz:item:list | 修改历史时间线 |
| PUT/DELETE | /items/:id | biz:item:update/delete | owner 本人 / 本家庭 family_admin / admin |
| GET/POST/PUT/DELETE | /categories | biz:category:* | member 只读；家庭级 |
| POST | /uploads | biz:item:create | multipart file ≤5MB → {url} |
| GET/POST/PUT/DELETE | /admin/families | sys:family:* | 仅 admin；删除前需清空成员 |
| POST | /admin/families/:id/transfer | sys:family:transfer | 家庭管理员移交 |
| GET/POST/PUT/DELETE | /admin/users | sys:user:* | admin 全量 / family_admin 强制本家庭 |
| DELETE | /admin/users/:id | sys:user:delete | body {receiverId}：物品责任整体移交 + TRANSFER 历史 |
| GET | /admin/audit-logs | sys:audit:list | admin 全量；family_admin 本家庭成员 |

## 7. 前端结构（`web/`）

- **路由守卫**：白名单直通 → 无会话先尝试 Cookie 静默恢复（fetchMe）→ 失败跳登录 →
  按 permCodes 过滤动态路由 `addRoute` → `to.meta.permission` 校验，无权跳 403。
- **axios 拦截器**：401 静默刷新 + 重放（全局单飞，并发只刷一次）；403/400 ElMessage。
- **accessToken 只存 Pinia 内存**，刷新页面靠 Cookie refresh 恢复——XSS 偷不走 7 天凭证。
- **v-permission 指令**：无权限码直接移除 DOM（按钮级）。
- **角色差别在"我的"页体现**：member 只见物品/分类；family_admin 多出成员管理+移交；
  admin 多出家庭管理/用户管理/审计日志。

## 8. 安全基线（对应设计稿 §7）

1. Argon2id（OWASP 首选），PHC 自描述格式，登录时透明升级预留
2. JWT HS256 + 算法白名单（拒绝 none/换算法），密钥 ≥256bit
3. 登录限流：Redis 计数 5 次/10 分钟；防枚举：统一文案 + 哑哈希恒定耗时
4. refresh：CSPRNG ≥256bit，只存 SHA-256 摘要，一次一换 + 重用检测
5. 登出/踢人：jti 黑名单 + family 撤销；改密/改角色/禁用主动撤销
6. Cookie：httpOnly + SameSite=Lax（生产 + Secure）
7. 边界纪律：每个接口中间件校验权限码 + handler 行级校验，前端隐藏只是体验
8. 审计：登录成败/权限变更/敏感操作/物品责任移交全落库
9. 上传：扩展名白名单 + 5MB 限制 + 随机文件名（原名不落地）
10. 图片存储与孤儿清理：两步上传（先 `/uploads` 拿 URL，再随物品 JSON 提交）的固有代价是
    会产生无引用文件（上传后放弃提交、编辑换图）。后台 janitor（`biz/janitor.go`）每小时对账：
    引用集合 = `biz_item.image` 全量（含软删行，可恢复故保守保留）；目录中无引用且 mtime
    超过宽限期（`UPLOAD_GRACE`，默认 24h，覆盖"传了图还在填表"）的文件删除，动作写审计。
    生产演进：多实例时换对象存储（MinIO/OSS）+ CDN，引用对账逻辑不变。
